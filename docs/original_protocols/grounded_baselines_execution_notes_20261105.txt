MATCHED GROUNDED LGBO / REASONING BO: EXECUTION AND INTERPRETATION

Scope
Eight frozen tasks; seeds 0, 1, 2, 3; zero free observations and twenty
sequential paid table evaluations per trajectory. The same chemically grounded
first input and blinded initial scientific hypotheses are shared across the
LLM methods. The initial LLM response is fixed across seeds. Downstream LLM
responses are fresh, isolated and separate by task, seed, method and round.
The numerical GP/MC stream remains seed 0; the all-query exact-tie stream uses
the registered seed. Thus these are conditional trajectory comparisons, not
independent repeats of initial LLM knowledge sampling.

Controls and resource accounting
The current hypothesis/KF/event method, same-first BO and zero-data-prior BO
are imported without rerunning or changing their outcomes. The same-first BO
control isolates the effect of decisions after the shared first experiment.
Zero-data-prior BO retains its own registered first draw. Experimental budgets
are matched, while LLM computation is not: LGBO and Reasoning BO each request
nineteen responses after the first experiment. Hypothesis refreshes are
event-triggered. New workload is sixty-four trajectories, 1,280 paid table
evaluations and 1,216 logical post-first requests, with at most two schema-only
attempts per logical request. Existing blind priors and first proposals are
reused explicitly and are not counted as new responses.

Scientific mechanisms
LGBO uses the vendored official regional posterior-mean tilt. Finite uniform
quadrature over executable input regions (maximum 512 support points) handles
the mixed domains. Its official confidence-to-delta function is retained,
including the vendor's float32 erfinv evaluation. The native covariance and
full-pool qLogEI are retained. The method has no hard hypothesis mask, KF,
event permissions or acquisition opportunity gate.

Reasoning BO uses the official English optimization template and the unchanged
stable confidence extractor. Its finite-pool interface chooses one of the GP's
five candidates per experiment. This is a sequential 5-to-1 adaptation, with
shared blind knowledge supplied as retrieved text and complete own Insight
history retained. It does not reproduce the paper's complete multi-agent
retrieval/database system or batch protocol. Rankings and numerical GP scores
are hidden; neutral display order exposes only top-five membership. These
results therefore compare explicit matched adapters and are not published-
protocol reproductions or direct literature leaderboard claims.

Numerical execution correction
The original preflight omitted singleton prefixes. The first attempted LGBO
singleton acquisition reconstruction failed its numerical agreement guard
before committing a new choice. Reported posterior variance may be floored,
whereas the native P0/P1 sampler uses covariance plus its original jitter.
Recovering qLogEI from the report-only marginal SD was therefore inaccurate
by approximately 2.1e-5 in log-acquisition units. The compatibility adapter
calls the original qLogExpectedImprovement directly on the same native model
and official tilted posterior, with the same 512 draws, seed and jitter. It
changes neither GP fitting nor the regional algorithm. Existing responses
were retained at their original prefixes; no performance-driven reroll was
made. All eight actual singleton prefixes passed native replay with maximum
errors from zero to 8.9e-16. P2 retains its original acquisition calculation.
See execution_compatibility.json and operational_interruption.json in the run.

Experimental LLM custody
Each logical request or schema repair is answered by a fresh independent
gpt-6.1-terra, medium child, fork_turns=none. A receipt-only coordinator may
spawn nested children but never reads scientific inputs or creates answers.
Actual canonical child identifiers are preserved in assignment and completion
receipts. No output is sealed merely because a file exists: an actual child
FINAL_ANSWER notification is required. The delegated transport registration
documents this operational change; scientific prompts and requests stay
frozen. Requested model settings are recorded; provider usage/attestation is
not independently available through this subagent backend.

Execution
Use the existing official Python environment. The supported runner is
  python code/experiment_tools/run_grounded_baselines_compat.py
It uses eight persistent CPU workers, one BLAS thread each, warmed operators
and exact-prefix numerical caches. It waits for authenticated experimental
LLM receipts. Running it without servicing requests does not fabricate LLM
responses. No cluster/GPU numerical backend substitution is made.

Reporting and validation (do not change experimental state)
  python code/tools/report_grounded_baselines.py
  python code/tools/audit_grounded_baselines.py --final
Before completion the report marks all missing trajectories explicitly and
the final audit refuses to pass. The read-only partial audit omits --final.
All code remains under code/; experiments/runs/ stores evidence and caches;
experiments/reports/grounded_baselines_20261105/ stores derived comparisons.

Metric definition
For a complete trajectory with twenty observations y_1,...,y_20,
  M_t = max(y_1,...,y_t),
  SearchAUC = sum(M_1,...,M_20)/20.
The first paid point, zeros and non-improving evaluations are included.
Final best is M_20. First attainment is the first paid query equal to M_20.
Means and sample SD are calculated separately within each task over all four
seeds. No raw objective is averaged across tasks with different units.
The optional ln_sum_cumulative_best field is exactly ln(20*SearchAUC) within
one trajectory. It is not asserted to equal any paper's Log AUC definition.
The exponential of a mean log is not the arithmetic mean SearchAUC.

Audit scope
The audit replays saved state transitions, verifies decision-before-feedback
receipts, all-pool availability and exact ties, RBO top-five membership and
official confidence extraction, LGBO physical scopes/quadrature/argmax, full
own-history prompts, actual LLM response custody, oracle row/scale matching,
and unchanged source/control hashes. It independently calculates SearchAUC
using a running maximum loop. It does not refit any GP or request new data.
Numerical posterior equivalence relies on the registered compatibility and
preflight checks plus the unchanged qualified source; it is not claimed to
be a new numerical re-evaluation of every posterior during the saved audit.
