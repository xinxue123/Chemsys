# 统一 BO 底座上的 B4 区域先验准入实验

本实验检验两个问题：B4 能否保留区域知识引导的收益；在知识错误时，它是否比单候选审查、单纯预算门限和全部撤销更有效。此前官方源码对照、B0–B4 研究及跨协议诊断均保持原样。

**冻结结果：本版 `B4_LGBO` 未通过事前验收，不能作为已经取得增量的方案。** 它保留了 83.53% 的正确知识引导收益，但正确知识下平均 SearchAUC 比区域 LGBO 低 1.06 个百分点；错误类别和混合错误合并后低 0.82 个百分点，也低于单纯预算门限 0.91 个百分点。下面同时保留负结果、原硬筛选 B4 的对照和实现核验。

## 方法与语义

所有方法使用同一个有限候选集、相同初始观测、GP 拟合规则、MC 样本与 qLogEI。每个案例的候选集包含原 512 点、每类催化剂 512 个额外 Sobol 点、64 个数值边界角点和原有五个种子的 20 个 LHS 初始条件，去重后为 4692 点。候选坐标生成不使用产率。各方法都禁止重复查询。

GP 直接使用固定官方 LGBO 源码中的 `BaseBOSampler.fit_model`，包括原来的目标标准化、BoTorch SingleTaskGP 和默认 RBF 核。输入为三个归一化数值坐标及固定催化剂区间码；后者仍存在任意标签顺序的距离偏差。所有方法使用相同的 512 路 MC-qLogEI 与随机种子。基础和引导模型都经过同一官方后验包装，因此均包含相同的 `1e-6` 协方差 jitter。

区域知识使用原 `LinearExponentialRegionalMeanTiltPlugAndPlay`，网格大小 512、置信度映射 `3 Φ⁻¹(c)`。本实验固定 `smooth=0.08`，只研究区域均值偏移，不进入此前发现权重相同的点先验分支。统一有限候选集和固定区域组件是本次实验的明确设置，因此 `LGBO_region` 是匹配组件对照，不等同于上轮官方完整 LGBO 算法。

设基础采集分数为 `a0(x)`，当前未查询候选中的最大值为 `a0*`。第 t 个新增查询允许的基础分数损失为

`epsilon(t) = log(r) * (16-t)/15, t=1,...,16`。

预算内集合为 `E = {x: a0* - a0(x) <= epsilon(t)}`，比较不增加隐含容差。开发集只在 `r=2,4,16` 中选择。第一轮指数化分数的最低保留比例分别为 1/2、1/4、1/16，最后一轮只能选择基础分数最大点。这保护的是同一 MC-qLogEI 评分的机会损失，不是真实产率保证或实验室安全保证。

每个区域拆成停留时间、温度、负载量和催化剂区间四条坐标经验，使用与真伪无关的固定随机编号。原 B4 求解器找出交集在 E 内有见证点的最大基数子集，并沿用原编号并列规则。

`B4_LGBO` 把这组保留经验作为**软先验准入结果**，向其交集区域注入均值偏移，再在 E 中最大化引导分数。实际查询可以处于偏好区域之外，因此不能把“保留经验”解释为每次查询都严格满足它。原来要求查询满足所有保留约束的语义单独由 `B4_base` 对照保留。

| 方法 | 决策 |
|---|---|
| B0 | 最大化未引导 qLogEI |
| LGBO_region | 保留完整区域偏好，最大化引导 qLogEI，不受基础评分预算约束 |
| B3_gate | 只审查一个完整引导提案；不在预算内则执行 B0 |
| LGBO_gate | 不撤销经验，直接在预算内最大化完整引导分数 |
| B4_base | 原联合最少撤销，随后在保留约束交集内最大化基础分数 |
| B4_LGBO | 联合最少撤销后注入剩余区域，在预算内最大化引导分数 |
| A2_LGBO | 完整经验组合可准入则全部采用，否则全部撤销；同样在预算内选点 |

`LGBO_gate` 用于排除“改进仅来自普通预算门限”的解释；`A2_LGBO` 用于判断部分撤销是否比全部撤销更有价值。

## 知识条件和真值边界

- `correct`：参考表最优点周围的区域，包含有限候选集最优点。
- `wrong_category`：保留参考区域的数值范围，把催化剂经验换成该范围内表现最差的一类。
- `mixed`：保留参考催化剂和温度经验，构造错误的停留时间、负载量区间。
- `assistant_initial`：使用此前真实助手在相同四个初始观测下给出的第一条区域建议，后续保持固定。

前三项是明确披露的**参考结果知情人工压力测试**。构造器用完整冻结反应表给知识贴真值标签；决策函数只接收经验谓词、已揭示观测和采集分数，不接收未查询产率或经验真伪。它们不能证明 LLM 能自动生成可靠化学知识。第四项保留真实来源，但没有新增 LLM 推理或自适应刷新。

正确经验在四个案例中均覆盖参考最优点。错误类别经验的区域最优值比参考最优低 33.09–65.87 个百分点，混合错误经验低 23.18–64.26 个百分点。已有助手初始建议的质量不预先保证；其区域最优损失为 0–49.31 个百分点。具体标签和每条经验的质量只写入评估文件，不进入选择器。

## 开发选择与正式比较

Case 1 用于开发选择；Case 2–4 用于冻结后的比较，每个案例五个相同初始种子。每条轨迹四次初始化、16 次新增查询。

开发阶段共 325 条唯一轨迹：基础 B0 在各知识条件间共享，未加预算的区域 LGBO 在不同预算选择间共享。其余五个方法评估全部三个预算比值。

开发选择先要求 `B4_LGBO` 在正确知识下距离区域 LGBO 的平均 SearchAUC 不超过 1 个百分点；若 LGBO 相对 B0 的增益至少为 1 个百分点，还须保留至少 80% 的增益。满足后，选择错误类别、混合错误两项中最差平均表现最高的预算；按平均表现和较小预算依次破同分。若没有预算满足正确知识保留条件，则按预先规定的 `r=16` 测试并保留开发失败证据，不宣称已取得开发资格。

冻结预算后，测试阶段共 375 条唯一轨迹。主要经验验收条件为：

1. 正确知识下平均 SearchAUC 损失不超过 1 个百分点，并按上述条件保留 80% 正增益。
2. 错误类别、混合错误条件下，平均 SearchAUC 相对区域 LGBO 提升至少 2 个百分点。
3. 在这些错误条件下，平均表现分别高于单候选审查、单纯门限及全部撤销对照。

这些是事前固定的描述性验收条件，不是三个反应案例上的总体非劣性或显著性证明。当前聊天已接触过全部案例的早期结果，本轮仍属探索性验证，不是盲评。

失败轨迹留在计划分母中，未用预算位置沿用最后 incumbent。预算合法、独立穷举一致和程序完成，只能证明实现与日志性质，不能代替上述收益目标。

## 冻结结果与解释

开发集 Case 1 按事前规则选出 `r=4`；该设置在开发集保留 92.74% 的正确知识收益。选择文件在测试轨迹生成前固定，测试过程中未重新选择预算或改动算法。325 条开发轨迹、375 条测试轨迹全部完成，共 700 条唯一轨迹、14000 次逻辑模拟器查询；本轮没有新增 LLM 推理。查询结果来自既有 Summit 冻结代理模型，不是真实新增化学实验。

下表是 Case 2–4、每个案例五个配对种子的 SearchAUC 均值（百分比，越高越好）。每个知识条件、每个方法的分母为 15 条轨迹；B0 在知识条件之间共享，不能重复计为独立运行。指标为 16 个新增查询位置的 incumbent 产率均值；四个初始化位置不计入 AUC，但其已有最优观测会延续到后续 incumbent。

| 方法 | 正确知识 | 错误类别 | 混合错误 | 助手初始建议 |
|---|---:|---:|---:|---:|
| B0 | 65.258 | 65.258 | 65.258 | 65.258 |
| LGBO_region | 71.680 | 66.674 | 66.493 | 69.709 |
| B3_gate | 70.409 | 66.538 | 65.930 | 69.564 |
| LGBO_gate | 70.525 | 67.205 | 66.147 | 69.506 |
| B4_base | 73.394 | 66.663 | 67.799 | 69.554 |
| B4_LGBO | 70.622 | 64.998 | 66.533 | 69.632 |
| A2_LGBO | 71.098 | 64.504 | 66.155 | 69.527 |

主要组合的四项验收中，只有“保留至少 80% 的正确知识正增益”通过。正确知识损失为 1.057 个百分点，超过 1 个百分点限值；错误/混合条件相对区域 LGBO 的平均增量为 −0.818 个百分点，未达到 +2 个百分点；相对单候选审查、预算门限、全部撤销分别为 −0.468、−0.910、+0.436 个百分点，未超过全部简单保护对照。错误类别相对预算门限的损失主要集中于 Case 2（−5.907 个百分点）；Case 3、4 分别为 −0.464、−0.249。

`B4_base` 是有价值的次要观察：正确知识下高于区域 LGBO 1.715 个百分点；错误/混合条件合并后高 0.647 个百分点。不过，它在错误类别一项没有改善均值，在助手初始建议回放中还比区域 LGBO 低 0.155 个百分点。这不能代替主要组合的事前验收，也不能证明它普遍更可靠。预算 `r` 针对主要组合选择，并非为原硬筛选 B4 单独优化。

### 撤销有效，不等于剩余经验适合均值注入

错误类别条件下，每个方法共有 240 个新增决策。主要组合仅在 24 次决策保留错误催化剂经验，即 216/240 次撤销该经验；实际只在错误催化剂上查询 13 次。原硬筛选 B4 分别为保留 23 次、查询 23 次；完整区域 LGBO 则查询错误催化剂 22 次。因此，主要组合失败不能仅用“保留了更多错误催化剂”或“查询了更多错误类别”解释。

主要组合在正确、错误类别、混合错误条件下，分别有 107/240、101/240、85/240 次查询处于保留偏好区域之外；原硬筛选 B4 均为 0。前者属于本实验明确允许的软先验语义，不能解释为硬约束违反。它说明“经验获准注入后影响 GP 均值”与“查询严格满足保留经验”是不同决策方式，不能只比较撤销数量就推断收益。

另一个关键边界是：错误区域不自动导致软引导策略的平均损失。完整区域 LGBO 在错误类别和混合错误条件下分别有 231/240、232/240 次查询在完整偏好区域之外，均值仍比 B0 高 1.416、1.235 个百分点。因而本轮不能声称“先造成了稳定损害，再被 B4 恢复”。仍存在逐轨迹损害：错误类别下相对配对 B0 的平均截断损失 `mean(max(AUC_B0-AUC_method,0))`，LGBO 为 0.711、主要组合为 1.277 个百分点，组合没有减少这项损失。

代码语义指出一个后续需要检验的假设：原建议表达的是**联合条件下的优选区域**。撤销催化剂限制后，剩余数值区域会扩展到所有催化剂，却继续使用原置信度进行均值抬升。联合区域中的位置偏好，不足以推出扩展区域整体具有较高函数均值；数值条件也可能依赖已撤销的催化剂。最大基数的预算可行子集只证明“存在采集分数预算内的见证点”，并不认证经验真伪或这种均值解释。

本轮硬/软对照同时改变了查询掩码和均值注入，不能把负结果单独归因于其中一项，也没有因果隔离条件置信度的影响。上述解释属于有日志支持的机制假设。应保留本轮测试，后续在新的开发协议中研究经验的条件依赖、撤销后的置信度和先验类型，分别隔离硬筛选与均值注入；不能在这批测试结果上反复调参后宣称验证成功。

### 实现核验与科学结论分别记录

13 个相关组件测试通过。独立核验重新计算全部 375 条测试轨迹的 7500 个预算位置，重建 6000 次策略选择，并对 1920 次 B4 决策独立穷举子集，均无不一致；基础评分预算违反为 0。此前 1610 个受保护文件均保持原样，记录的循环内算子编译次数为 0。核验回执中的 `status=PASS` 只表示这些检查通过，`empirical_acceptance.all_gates_met=false` 才是本轮主要收益目标的结论。

原始均值和按案例比较见 [results.json](../research/suzuki_guarded/results.json)，撤销与选点计数见 [wrong_category_mechanism.json](../research/suzuki_guarded/wrong_category_mechanism.json)，完整核验见 [validation_receipt.json](../research/suzuki_guarded/validation_receipt.json)。结果图和计数可分别用 `python -m scripts.plot_guarded_suzuki`、`python -m scripts.analyze_guarded_suzuki_mechanism` 重新生成，不产生新查询。

## 执行和复现

入口为 `python -m chem.benchmarks.suzuki_guarded`，使用既有 `.venv-official`。每个持久进程一个 BLAS/PyTorch 线程，五个独立种子进程并行。导入和矩阵算子预热在循环前完成；每个不同历史只拟合一次，所有方法复用准确匹配的 GP/采集分数缓存。

```powershell
.venv-official\Scripts\python.exe -m chem.benchmarks.suzuki_guarded prepare
.venv-official\Scripts\python.exe -m chem.benchmarks.suzuki_guarded develop
.venv-official\Scripts\python.exe -m chem.benchmarks.suzuki_guarded freeze
.venv-official\Scripts\python.exe -m chem.benchmarks.suzuki_guarded test
.venv-official\Scripts\python.exe -m chem.benchmarks.suzuki_guarded report
.venv-official\Scripts\python.exe -m chem.benchmarks.suzuki_guarded verify
```

协议、开发选择、结果及核验依次保存在 [protocol.json](../research/suzuki_guarded/protocol.json)、[selected_budget.json](../research/suzuki_guarded/selected_budget.json)、[results.json](../research/suzuki_guarded/results.json)、[validation_receipt.json](../research/suzuki_guarded/validation_receipt.json)。原始轨迹与缓存位于 `data/runs/suzuki_guarded/`。不应将不同知识条件下共享的 B0 或同一反应案例的五个种子视为新增独立化学体系。
