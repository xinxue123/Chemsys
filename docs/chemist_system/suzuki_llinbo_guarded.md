# 官方 LLINBO 接入统一底座：逐轮助手候选实验

本轮将 LLINBO 的逐轮候选审查机制接入既有统一候选集、初始化、GP、qLogEI 和查询预算，与区域 LGBO、仅预算门限、原硬筛选 B4、B4+LGBO 比较。名称为 **LLINBO-Matched**。它是基于官方执行循环的匹配适配版本；此前原生 UCB 的官方实验继续保留。

**完成结果：80/80 条轨迹完成，1280 条逐轮助手建议均留档。** Case 2–4 的均值在四种知识条件下均居首，但错误类别下与单纯预算门限几乎持平；该条件的 Case 2 还明显落后。结果属于本聊天共享上下文、带候选投影和逐轮点建议的系统比较，不能归因为官方审查规则本身。

## 冻结设置

- Reizman Suzuki Case 1–4，各五个种子、四种相同初始知识条件，共 80 条 LLINBO 轨迹。Case 2–4 的 60 条用于与上一轮正式比较对应，Case 1 只作参考。
- 每个案例沿用 4692 个公共候选和相同四次初始观测，再执行 16 次新增查询；计划 1600 次逻辑模拟器查询、1280 条逐轮助手回答。
- 同一官方 LGBO GP/RBF 拟合、目标标准化、512 路 MC-qLogEI、随机种子与协方差 jitter。门限沿用上一轮 Case 1 已冻结的 `r=4`，不重新选参。
- 四种知识条件均把原来的四条经验作为不保证正确的助手上下文。助手每轮结合本轨迹已揭示结果提出一个物理条件。区域对照仍使用原固定初始区域，所以这比较的是两种知识使用系统，不能隔离“相同动态知识”下的决策器差异。
- 对照复用此前冻结轨迹，按 case/seed/knowledge 一一配对，不重新生成或挑选。全部计划轨迹保留；失败后用最后 incumbent 延续预算位置。

## 官方执行与必要差异

固定官方提交为 `105701dffee2999f31de1c0f42241d0e82b48e55`，实际入口仍为 `LLMIBO_BFO.run → _run_justify`。vendor 文件不修改，源代码中的 `if base_score > proposal_score + threshold` 拒绝分支及 `else` 接受分支直接执行。

| 项目 | 官方原生设置 | 本轮统一设置 |
|---|---|---|
| 初始化 | LLM warm-start | 公共四次初始化 |
| GP | 官方 LLINBO `train_gp` | 统一官方 LGBO GP 拟合 |
| 候选与最大值 | 连续 UCB 搜索 | 在公共未查询候选上求基础 qLogEI 最大值 |
| 审查评分 | UCB，原 beta | 共享基础 qLogEI；原 beta 计算并记录，但不参与评分 |
| 机会损失门限 | 初始最大后验方差/t | 既定 `log(4)*(16-t)/15`；通过原除法位置的 `MatchedThreshold` hook 提供 |
| LLM | 原 API 调用 | 当前助手逐条提供；保留官方提示构造和 JSON 向量解析 |
| 条件传输 | 任意单位立方体向量 | 助手给物理条件，按归一化三个数值坐标，投影到同催化剂的最近未查询公共点 |
| 重复与暂停 | 原循环顺序执行 | 禁止重复；精确前缀暂停恢复，历史查询回放不新增计费 |

投影只读取坐标和已查询 ID，不读取 GP 分数或未查询产率；原建议、投影后候选及距离全部留档。每个前缀固定提示打乱种子，保证恢复和缓存不会改变原提示。

## 助手证据边界

公开任务用不含 case 和知识真伪标签的编号。首轮显示初始观测和经验区间；后续显示最新实际观测、incumbent、仅由已观察数据汇总的各催化剂最好结果。完整官方提示和观测前缀均留档。助手不接收 BO 排名、被拒候选产率或其他方法轨迹。

实际助手在本聊天中读取观测摘要；部分轮次按相同最新观测与 incumbent 合并展示，完整前缀仍保存在请求中。没有把每条保存的完整原提示作为独立 API 请求。助手显式填写每个任务的物理候选、理由和已揭示查询引用；同建议组只按助手列出的任务编号机械展开，脚本不生成或排名候选条件。

本聊天已经接触全部案例的旧结果与人工压力测试描述；匿名编号不能消除这种暴露。本轮不是盲评、独立 API 样本或不可变模型版本测试。前三种经验条件仍是参考结果知情人工压力测试，不能据此声称 LLM 自动生成了正确化学知识。

## 执行

入口为 `python -m chem.benchmarks.suzuki_llinbo_guarded`：`prepare` 固定协议，`run` 启动八个单线程持久 CPU 进程，`view --initial`/`view` 读取仅含观测的待答视图，`submit --answers ...` 转录助手实际建议，`report` 和 `verify` 汇总、核验。导入和矩阵预热在计数循环前完成，记录循环内 JIT 调用。

协议与结果目录为 `research/suzuki_llinbo_guarded/`，逐轮请求、回答、原始建议、投影、观测和审查记录位于 `data/runs/suzuki_llinbo_guarded/`。算法实现核验与优化收益分别报告。

## 冻结后的比较结果

以下为 Case 2–4、每个案例五个配对种子的 SearchAUC 均值（%，越高越好），每格分母为 15 条轨迹。主指标是 16 个新增查询位置的 incumbent 产率均值；初始化位置不计入 AUC，初始最好观测会延续到后续 incumbent。B0 同底座均值为 65.258%，在各知识条件间共享，不增加独立运行数。

| 方法 | 正确知识 | 错误类别 | 混合错误 | 助手初始建议 |
|---|---:|---:|---:|---:|
| LLINBO-Matched | **73.755** | **67.210** | **71.076** | **71.243** |
| 区域 LGBO | 71.680 | 66.674 | 66.493 | 69.709 |
| 仅预算门限 | 70.525 | 67.205 | 66.147 | 69.506 |
| 原硬筛选 B4 | 73.394 | 66.663 | 67.799 | 69.554 |
| B4+LGBO | 70.622 | 64.998 | 66.533 | 69.632 |

LLINBO-Matched 相对区域 LGBO 的四项均值差依次为 +2.076、+0.536、+4.582、+1.534 个百分点，相对原硬筛选 B4 为 +0.361、+0.547、+3.277、+1.689 个百分点。错误类别和混合错误合并后，它的均值为 69.143%，相对区域 LGBO、单纯门限、原硬筛选 B4、B4+LGBO 分别高 2.559、2.467、1.912、3.377 个百分点。

这些均值不能解释为逐案例、逐种子或风险指标全面胜出。错误类别下，它比单纯门限仅高 0.005 个百分点，15 个配对中为 8 胜、7 负；按 Case 2/3/4 分解为 −5.450、+5.804、−0.339 个百分点，均值接近是案例之间相互抵消。正确知识下，相对原硬筛选 B4 的 Case 2 差为 −0.442 个百分点。混合错误下相对原硬筛选 B4 为 14 胜、1 负，三案例均值差均为正，但这仍是三个反应场景上的探索性结果。

已有助手初始建议条件下，相对 B0 的平均增益为 +5.984 个百分点；相对区域 LGBO 的案例差为 +4.148、+0.879、−0.425 个百分点。这里每轮点建议会随观测更新，区域方法保持初始建议不变，更新频率是比较中的实质差异。

平均风险也需要分别保留。以配对 B0 为参照，计算 `mean(max(AUC_B0-AUC_method,0))`，错误类别下 LLINBO-Matched 为 0.814、门限为 0.737、原硬筛选 B4 为 0.747 个百分点；助手初始建议条件下 LLINBO-Matched 为 0.423、原硬筛选 B4 为 0.158 个百分点。均值领先不足以证明错误知识损失或尾部风险全面更小。

## 建议采纳、投影与归因边界

全部四个案例共 1280 条助手提案，官方分支接受 313 条（24.45%）、拒绝 967 条。Case 2–4 的 960 条中接受 245 条，其中 214 条实际改变了同一观测前缀下的基础 BO 选点。各条件接受数为正确知识 61/240、错误类别 59/240、混合错误 59/240、助手初始建议 66/240。这些比例使用的是本轮共享 qLogEI 和门限，不能与旧原生 UCB 实验的采纳率直接归因为模型能力变化。

有限池投影是有实际影响的算法适配。正式比较中，四个条件的归一化数值坐标投影距离均值依次为 0.111、0.093、0.111、0.110，最大值为 0.219（归一化停留时间、温度、负载量的欧氏距离）。960 条提案中有 564 条的最近公共点已经测过，适配器因禁止重复而转到其他同催化剂近邻。这提供了额外的近邻探索，不能将整个结果当作原生连续 LLINBO 的表现。

混合错误条件中，15 条原始物理建议位于完整经验区域内，投影后这些建议均离开该区域；全部 240 条投影后提案均在完整错误区域之外。因此不能把“全部离开错误区域”都解释成 LLM 主动识别错误。它同时反映了建议更新、有限池几何和未查询点投影的共同作用。投影详细计数见 [projection_diagnostics.json](../research/suzuki_llinbo_guarded/projection_diagnostics.json)。

全部回答冻结后，评估器使用固定代理表检查被拒候选，仅作离线单步诊断。四条件分别有 26、57、32、34 条被拒提案，其模拟产率高于当时 incumbent；149、135、146、144 条被拒提案的模拟产率高于当步实际执行点。它说明采集分数门限不是单步产率保证；这些反事实不能推出取消门限后整条轨迹必然更好，也没有把这些值提供给当时的助手或选择器。

目前可以支持的结论是：在这套共同底座和明确的传输适配下，逐轮点建议加单候选审查构成了应保留的强对照，尤其在混合错误知识条件下。后续 B4 的增量需要与该对照比较；本轮没有证明联合最少撤销比它更有效，也没有隔离投影、建议更新频率和审查规则各自的贡献。

## 完整性核验

18 项组件测试通过。独立核验检查全部 80 条轨迹的 1600 个查询位置、1280 次接受/拒绝决策及候选投影，未发现重复候选或预算违反。80 个首轮基础评分表与父实验逐点相同，最大绝对误差为 0；400 次对照初始化配对一致。

另用全部保存回答，从实际官方入口不中断回放了 1280 次决策，原提示、选点和审查事件与暂停执行完全一致；回放没有新增拟合、采集函数计算、助手回答或模拟器观测。此前 754 个统一实验交付文件和 1610 个原生官方实验文件保持不变，循环内记录的 JIT 编译调用为 0。

协议哈希为 `b8f4ec3b43d3d2a579f39772d466161f5183e800d66e49667a295839ac01976d`。证据见 [protocol.json](../research/suzuki_llinbo_guarded/protocol.json)、[results.json](../research/suzuki_llinbo_guarded/results.json)、[validation_receipt.json](../research/suzuki_llinbo_guarded/validation_receipt.json)。核验通过证明协议执行和证据一致，不将它解释为普遍科学优势。
