# 智能体全候选评分与实验反馈：Suzuki Case 1–4

**已完成：当前智能体每轮制定评分规则，对全部候选评分，执行最高分的未查询候选，并将新结果带入下一轮。** 不使用 GP、UCB、EI 或 BO 审查门限。40 条新轨迹包括 20 条经验更新策略和 20 条冻结首轮规则的对照，全部完成。当前数据是既有 Suzuki 模拟器返回值，不是新增湿实验。

## 方法边界

这里的“智能体打分”采用**当前对话智能体逐轮编写可执行评分卡**：每条轨迹每轮一张，规则应用于全部 4692 个候选，统一选择最高分的未查询点。它不是把每一个候选分别交给独立 LLM API 判断；没有 150 万次 LLM 调用。共 320 张智能体评分卡，生成 **1,501,440 个候选分数**，逐点分数与决策均已保存。

评分规则限定为一个预先冻结的非线性形式：

`score(x) = catalyst_bias[c] − Σ curvature[j]*(z[j]−target[j])² + novelty_weight*nearest_same_catalyst_distance(x,H) + Σ anchor_bump(x,h_a)`

其中 z 是三个连续变量的归一化坐标。智能体为 8 类催化剂指定偏置，为数值变量指定目标与曲率，指定探索权重，并可增加至多 8 个围绕既有观测的正或负高斯记忆项。新类别的几何新颖度为 1，既有类别使用到本轨迹最近已观测点的三维归一化距离。这里的新颖度不是 GP 方差，也没有覆盖率或风险校准含义。分数是决策效用，不是有校准含义的收率预测。

每张卡的参数、解释和支持观测索引由当前智能体手动提供；程序只验证、展开字段、计算已给定公式和取最大值，没有自动回归拟合、调用其他 LLM 或用隐藏收率选权重。所有卡使用同一个向量化 NumPy 算子，没有运行中动态生成、编译或执行代码。

该规则族限制了智能体的表达能力，因此结果应称为 **Agent_score_adaptive：智能体规则评分策略**，不能泛化成任意“纯 LLM 对全部点独立打分”的成绩。

## 公平条件与经验控制

- 与已有 BO 对照相同的 Reizman Suzuki Case 1–4、每例 5 个种子、4692 个候选点。
- 使用每条轨迹完全相同的 4 个原始初始化点与收率；追加 16 个不重复候选。
- 不附加四种预设区域知识，输入与无知识 B0 对齐。给当前智能体的视图只含类别、实验坐标和已查询收率，使用匿名任务编号，不展示 BO 分数、未查询收率或知识质量标签。
- 每轮先保存请求、评分卡及全候选分数、确定 ID，随后读取所选点的 oracle 结果。新结果成为下一轮的经验。320 张评分卡分 16 批保存，每批 20 条轨迹各一张。
- 320 张自适应卡全部冻结后，才运行冻结首轮规则对照。该对照始终使用第一张卡及最初 4 点的几何信息，只有已查询 ID 屏蔽集变化。因此分数可缓存，后续收率不影响评分。
- 40 条新轨迹共 800 次逻辑查询，包括 160 次初始化计数和 640 次追加计数。动态策略 400 次、冻结策略 400 次；共享初始化仍按各方法逻辑预算计数。未新增 BO 轨迹。
- qLogEI、原 β UCB、κ=2 UCB 的无知识 B0 结果只读复用；κ=2 沿用旧 Case 1 的选择，没有重新调参。沿用 Case2–4 主要比较、Case1 参考与四案例补充的报告划分。

所有轮次的评分卡均可找到本轨迹支持观测。例如，前 4 轮完成尚未观察的催化剂覆盖；之后各轨迹分别尝试升温、降温、调整停留时间和负载量，也在停滞后重新测试早先只在较弱条件下观察过的催化剂。后期部分轨迹选择保持评分偏好不变，这仍是一次新的基于当前记录的决策。

冻结控制比较的是整个反馈策略的作用，包括评分卡改变和新观测的几何信息改变。不能仅用二者的差值，声称已隔离“收率反馈语义本身”的纯因果贡献。验证器另给出固定实际历史、保留最新几何信息、只将卡替换为首轮卡的选点差异诊断；它不产生新的闭环成绩。

## 指标结果

SearchAUC 为 16 个追加位置的 incumbent 收率均值，单位为收率百分点，越高越好。Final 是最后的最好收率，不是最后一次实验的收率。所有计划轨迹均保留；若发生失败，应携带最后 incumbent 补足预算，不能剔除失败分母。本次无失败。

四案例共 20 条配对轨迹：

| 方法 | 平均 SearchAUC | 平均最终最好收率 |
|---|---:|---:|
| 智能体评分，逐轮更新经验 | **73.1256** | **79.1119%** |
| 智能体评分，冻结首轮规则 | 61.5353 | 63.4471% |
| qLogEI B0 | 67.5558 | 75.1800% |
| UCB 原 β B0 | 67.6090 | 72.1840% |
| UCB κ=2 B0 | 67.9880 | 72.5661% |

四案例自适应相对冻结策略 AUC **+11.5903**，20 胜 0 负；相对 qLogEI **+5.5699**，16 胜 4 负；相对 κ=2 UCB **+5.1376**，16 胜 4 负。

Case2–4 主要比较，共 15 条配对轨迹：

| 方法 | 平均 SearchAUC | 平均最终最好收率 |
|---|---:|---:|
| 智能体评分，逐轮更新经验 | **70.3613** | **75.6262%** |
| 智能体评分，冻结首轮规则 | 59.2330 | 60.8273% |
| qLogEI B0 | 65.2583 | 71.8527% |
| UCB 原 β B0 | 65.5459 | 68.2323% |
| UCB κ=2 B0 | 65.8311 | 69.3803% |

主要比较的反馈策略增量 **+11.1284**，15 胜 0 负；相对 qLogEI **+5.1030**，12 胜 3 负；相对 κ=2 UCB **+4.5303**，11 胜 4 负。最终最好收率分别多 **14.7989、3.7734、6.2459** 个百分点。

逐案例结果，每案例 5 个种子：

| 案例 | 更新经验 AUC | 冻结规则 AUC | qLogEI AUC | UCB κ=2 AUC | 更新经验最终最好收率 |
|---|---:|---:|---:|---:|---:|
| Case 1 | 81.4186 | 68.4423 | 74.4482 | 74.4590 | 89.5690% |
| Case 2 | 34.1831 | 17.8873 | 23.8472 | 19.9790 | 40.0853% |
| Case 3 | 83.5321 | 69.3919 | 79.7744 | **85.2143** | 90.7099% |
| Case 4 | 93.3687 | 90.4196 | 92.1533 | 92.2999 | 96.0832% |

优势存在案例差异。Case 3 上 κ=2 UCB 的过程 AUC 更高 **1.6822**，智能体不是每个案例都胜过 UCB。主要比较相对 qLogEI 的增量分别为 Case 2 **+10.3359**、Case 3 **+3.7577**、Case 4 **+1.2155**，总体优势受 Case 2 较大增量影响。

主要 240 次追加查询中，自适应策略有 **79/240** 次改善 incumbent，冻结规则为 **26/240**，qLogEI 为 **71/240**，κ=2 UCB 为 **52/240**。追加实验的平均实际收率分别为 **63.8500%、40.2314%、54.1067%、57.2117%**。

这些补充指标很重要：AUC 会保留最好结果，后期低收率实验不会拉低已经达到的 incumbent。一些轨迹在平台后继续尝试但没有改善，不能只凭高 AUC 断言每次建议都可靠。

## 对第五章的含义与限制

这次在既有模拟器上观察到：当前智能体规则评分策略可以利用逐轮经验取得比冻结首轮规则、现有纯 BO 对照更高的平均指标。因而后续研究 B4 等审查机制时，应把这个会持续更新的智能体策略纳入基线，避免把“会更新经验”与“审查知识”的收益混在一起。

它尚不能证明大语言模型普遍优于 BO，或化学知识已经得到可靠验证：

1. 当前对话已接触旧案例结果；多条轨迹共享上下文，没有独立模型快照、隔离会话或严格盲法。匿名编号和仅允许引用本轨迹记录不能消除共享上下文的信息暴露。
2. 所用的是受限的智能体评分规则，不是逐点独立 LLM 判断。规则偏好、几何探索、人工式的逐轮推理共同构成策略；不能将全部收益归因于化学知识。
3. 催化剂标签没有配体结构，智能体不能据标签推断具体化学性质；本实验主要检验观察反馈下的决策策略。
4. 只有 4 个模拟环境、每例 5 个初始化种子，主要比较只有 3 个反应环境。以上是描述性配对结果，没有统计显著性或跨体系泛化结论。
5. 本次没有四种错误知识压力条件、GP 可信度审查或池外方案生成；也未将输入不同的旧 LLINBO 区域知识结果混入公平排名。

## 复核与复现

入口：在 `chemist_system` 中使用固定环境 `.venv-official/Scripts/python.exe -m chem.benchmarks.suzuki_agent_score`。

动作：`prepare` → `view` → `submit data/runs/suzuki_agent_score/batches/roundNN.json`（16轮）→ `frozen` → `report` → `verify` → `release`。评分卡不能用脚本自动从新收率生成；本次所有 320 张均由当前智能体提供，脚本只执行既定数值算子。

重新从零测试需要新的运行目录与真正的新智能体回答。对当前冻结文件重放只是复现记录，不能计作新的独立 LLM 重复实验。`submit` 支持相同批次的幂等重放；`all_cards_frozen.json` 保存控制启动前的卡与轨迹散列。

主要文件：

- `research/suzuki_agent_score/protocol.json`：运行前冻结的范围、评分规则和科学源码散列。
- `data/runs/suzuki_agent_score/batches/round01.json` … `round16.json`：原始 320 张评分卡与相应选择回执。
- `data/runs/suzuki_agent_score/requests/`：完整已观测历史请求、对应评分卡回答，按上下文 SHA256 索引。
- `data/runs/suzuki_agent_score/scores/`：320 个完整 4692 维候选评分向量。
- `research/suzuki_agent_score/results.json`、`metrics.csv`、[曲线图](../research/suzuki_agent_score/incumbent_curves.png)：逐轨迹指标、配对差异与图表。
- `research/suzuki_agent_score/validation_receipt.json`、`release_receipt.json`：独立重算与旧文件只读核验结果。

在本地 CPU 上以 8 个线程并行执行各轨迹评分；NumPy 数值算子使用既有二进制实现，预热后执行。无 GP 拟合、动态代码求值、JIT 或运行中算子编译，计算不依赖集群或 GPU。评分计算计时不包括智能体思考与对话工具传输时间，不据此宣称端到端 LLM 更快。
