# DeepSeek 真实 API 智能体评分：缩减版 Suzuki 测试

本实验按用户要求使用工作区根目录 `config.txt` 指定的 DeepSeek 官方接口，模型名称固定为 **`deepseek-flash`**。模型每轮接收本轨迹已观测实验记录，返回评分卡，程序对完整候选池打分并执行最高分的未查询点。新收率进入下一轮历史。

**缩减版已完成：64/64轮真实API决策、4条自适应与4条冻结对照均跑满预算；接口错误和格式修复均为0。** 四案例同种子平均 AUC=67.4891，相对 qLogEI 高1.5632；Case2–4 主要比较仅高0.9547，且低于原β UCB 0.3013。因此这次小规模测试支持“反馈比冻结首轮规则更有用”，不能宣称稳定超越 BO。

## 完成结果

全部比较均只取 **seed=0**，不是此前5种子的均值。四案例平均如下：

| 方法 | SearchAUC | 最终最好收率 |
|---|---:|---:|
| DeepSeek 评分卡，逐轮更新 | **67.4891** | **74.9811%** |
| DeepSeek 冻结首轮评分卡 | 55.2882 | 57.1378% |
| qLogEI B0 | 65.9259 | 70.9822% |
| UCB 原β B0 | 65.8706 | 70.5496% |
| UCB κ=2 B0 | 65.7993 | 70.2061% |
| 旧当前助手规则，仅作上下文不同的参考 | 75.1117 | 78.9976% |

DeepSeek 相对冻结卡的 AUC 增量为 **+12.2010**，4例均为正；相对 qLogEI 为 **+1.5632**，3胜1负；相对 κ=2 UCB 为 **+1.6899**，3胜1负。相对旧当前助手参考为 −7.6225；该差异同时包含模型、提示、上下文与既往信息暴露，不能解释为纯模型能力差异。

逐案例结果：

| 案例，seed0 | DeepSeek AUC | 冻结卡 AUC | qLogEI AUC | UCB 原β AUC | UCB κ=2 AUC | DeepSeek 最终最好收率 |
|---|---:|---:|---:|---:|---:|---:|
| Case 1 | 74.0757 | 35.2338 | 70.6867 | 66.6976 | 70.7980 | 84.1603% |
| Case 2 | 21.3088 | 15.0696 | 18.5746 | 19.1948 | 17.0648 | 31.3871% |
| Case 3 | 84.1998 | 81.8448 | 82.9735 | 84.7626 | **87.2316** | 88.3456% |
| Case 4 | 90.3723 | 89.0045 | 91.4688 | **92.8274** | 88.1026 | 96.0312% |

沿用以前的 Case2–4 主比较口径：

| 方法 | SearchAUC | 最终最好收率 |
|---|---:|---:|
| DeepSeek 逐轮更新 | 65.2936 | **71.9213%** |
| DeepSeek 冻结首轮卡 | 61.9730 | 63.0064% |
| qLogEI B0 | 64.3390 | 69.2012% |
| UCB 原β B0 | **65.5949** | 69.0689% |
| UCB κ=2 B0 | 64.1330 | 69.5896% |

主比较的反馈增量只有 **+3.3207**；四案例 +12.2010 的较大均值受 Case1 的 +38.8419 影响明显。主比较相对 qLogEI 为 **+0.9547**（2胜1负），相对原β UCB 为 **−0.3013**（1胜2负），相对 κ=2 UCB 为 **+1.1606**（2胜1负）。

过程与终点也不总一致：Case3 的 DeepSeek AUC 高于 qLogEI，但最终最好收率低1.2955点；Case4 的 AUC 低于 qLogEI 1.0965点，但最终最好收率高1.4013点。不能只选有利指标下结论。

64次追加查询中，DeepSeek 有21次改善 incumbent，冻结卡13次，qLogEI17次。追加实验的平均收率分别为57.6762%、44.7733%、53.7364%。AUC 会保留已经达到的最好结果，因此这些实际查询指标帮助识别后期未改善或低收率建议。

缩减版本收到64个 API 回答，全部首次通过验证；输入82422 tokens、输出364093 tokens、合计446515 tokens，其中352274个思考tokens已包含在输出计数内，不能再加一次。API 返回模型名称均为 `deepseek-flash`，观察到的指纹一致；这仍不等于不可变模型版本保证。原中断尝试的用量单独列在结果中，不混入64轮正式指标。

## 缩减后的固定范围

用户要求减少评估数量后，固定采用 **Case 1–4 各一个 seed=0**。每条轨迹仍为 **4 次原始初始化＋16 次追加查询**，与 BO 的单轨迹预算一致。

- 4 条自适应轨迹，共 64 次有效智能体决策。
- 4 条冻结首轮评分卡的控制轨迹，不新增 LLM 调用。
- 合计 8 条新轨迹，160 次逻辑查询；其中初始化按各方法重复计32次，追加查询128次。
- 每次对同一套 4692 个候选完整打分。64 轮自适应选择共 300288 个候选分数，全部保存。
- 对照只读复用原 qLogEI B0、UCB 原 β B0、UCB κ=2 B0 的 **相同 seed=0** 轨迹。旧当前对话智能体的同种子结果单独作为参考；不与其5种子总体均值直接比较。

初始化种子按编号固定，不按收率或算法输赢选择。缩减时，4 条选中的原始 seed=0 轨迹均没有有效追加观测，因此在新目录独立启动。

## 评分与模型输入

复用此前冻结的 `agent_score_suzuki_engine.py`，不修改评分规则族：8 类催化剂效用偏置、3 个连续变量目标与曲率、几何新颖度权重，以及至多8个围绕既有观测的有符号高斯记忆项。每轮的全部参数与解释均由 API 返回，程序只做 JSON 验证、向量化计算、屏蔽已查询点和确定性取最大值。

**这是 LLM 制定规则后的全池评分，不是对4692个候选逐点分别调用LLM。** 不使用 GP、UCB、EI、局部回归器、人工补卡或其他模型替代失败的 DeepSeek 回答。候选池不扩展。

每次 API 请求只有固定系统提示与本轨迹完整观测、上一张评分卡。归一化坐标保留4位小数、收率百分数保留3位小数，与上一轮当前助手可见视图的精度一致。请求没有显式 Case 字段，任务编号只用于关联记录；编号和初始数据并不保证盲法或排除预训练记忆。API 不接收其他种子轨迹、其他方法分数、区域知识质量标签或未查询收率。匿名催化剂标签没有具体配体结构，不据标签编造化学属性。

每轮依次保存输入上下文、API 请求、回答、评分卡和完整候选分数，确定选中 ID 后才读取其模拟器收率。HTTP 连接复用不表示共享模型对话；各请求均重新携带该轨迹自己的状态。

## 接口、资源与必要适配

请求模型为 `deepseek-flash`，启用思考模式、`reasoning_effort=high`。这与当前官方默认一致；思考模式下温度参数不生效，因此没有声称设置 temperature=0 可保证确定性。[DeepSeek 思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)

初次接口核验使用合成观测并成功返回合法评分卡。后续原20轨迹计划受到 HTTP429、HTTP402 影响，停在35张有效卡、39个已返回响应；另有4个响应因长度截断无效。该中断尝试的请求、部分历史和用量保存在 `research/suzuki_deepseek_agent/interruption_receipt.json` 及对应只读清单，不作为完成的优化成绩，也不混入当前4轨迹。

缩减版进行了明确记录的接口调整：

- 并发从8降为2。
- `max_tokens` 从8192提高至16384，包含思考与最终回答的输出预算，减少 JSON 在思考完成前被截断的情况。
- 每个决策最多接收3次模型回答进行格式修复；最多8次 HTTP 尝试。429、5xx及传输错误在同一实验前缀退避重试，不获取额外实验收率。首次合法评分卡即被采用，不按后验收率挑选回答。
- 401或402触发全局停止，阻止队列继续发送新调用；不会用人工评分或 BO 选点补足。

这改变了接口资源设置，因此本次不能视为与原共享对话助手之间只替换模型名称的严格消融。规则算子、候选池、初始化和16次查询预算保持一致。官方模型别名与返回的模型标识也不等于不可变模型快照。[模型接口说明](https://api-docs.deepseek.com/)、[错误码说明](https://api-docs.deepseek.com/quick_start/error_codes/)

`config.txt` 只在运行时读取；密钥不复制、不计算散列、不写入请求正文、实验清单或日志。保留回答的 JSON 内容、ID、模型标识、可用指纹及 token 用量；不保存私有思考文本，只记录其长度与散列。

评分使用已有 NumPy 二进制算子，先预热，再向量化计算。无 GP 拟合、运行中 JIT 或算子编译。这里主要耗时为外部 API 推理，不依赖集群 GPU。

## 指标与结论边界

SearchAUC 是16个追加查询位置的 incumbent 收率平均值，以百分点计。Final 是所有20次观测中的最好收率，不是最后一次实验的收率。失败轨迹保留在计划分母中，并携带最后 incumbent 补足未完成位置。

本轮只有 **每案例一个初始化种子**，是降低费用后的探索性小规模检查。Case2–4 是与此前主比较口径对齐的3个环境实例，四案例均值作为完整范围展示。没有种子重复，不能估计案例内方差或宣称统计显著。

冻结首轮控制始终使用第一张有效卡及最初4点的几何信息，只改变已查询 ID 排除集。其差异衡量整个反馈策略，包括评分参数更新和新观测几何信息更新，不能单独归因于收率语义或化学知识。

旧当前助手参考使用共享对话，已接触其他案例结果；当前 DeepSeek 使用隔离的本轨迹请求。二者的差异同时包含提示、上下文和提供者差异，不能直接解释为模型本身能力高低。模拟器返回值也不代表新增真实湿实验。

催化剂在评分卡中使用独立类别偏置，而既有 GP 底座保留了原先的类别区间编码。这也是策略与表示方式的差异之一。因此，即使智能体指标更高，也不能将全部增量归因于语言模型的化学知识；本轮没有额外运行类别表示或评分规则族的消融，以遵守缩减后的评估范围。

## 运行与证据

工作目录为 `chemist_system`，环境为 `.venv-official/Scripts/python.exe`。唯一缩减版入口：

```powershell
.venv-official/Scripts/python.exe -m chem.benchmarks.suzuki_deepseek_small prepare
.venv-official/Scripts/python.exe -m chem.benchmarks.suzuki_deepseek_small run
.venv-official/Scripts/python.exe -m chem.benchmarks.suzuki_deepseek_small frozen
.venv-official/Scripts/python.exe -m chem.benchmarks.suzuki_deepseek_small report
.venv-official/Scripts/python.exe -m chem.benchmarks.suzuki_deepseek_small verify
.venv-official/Scripts/python.exe -m chem.benchmarks.suzuki_deepseek_small release
```

默认配置路径为 `../config.txt`，可使用 `--config` 显式指定。完成轨迹和已验证回答会复用；从冻结记录重放不是新的独立 LLM 重复实验。重新测试不同参数或不同预算应另建协议，不能覆盖本轮证据。

证据目录为 `data/runs/suzuki_deepseek_small/`：`requests` 保存隔离上下文和真实API回答，`scores` 保存全池评分向量，`runs` 与 `frozen` 保存两种策略轨迹。汇总结果、CSV、图、核验回执与文件清单保存在 `research/suzuki_deepseek_small/`。

最终数值以该目录的 `results.json` 为准。`validation_receipt.json` 核对原始输入、API回包、独立评分重算、相同初始化与预算以及全部旧证据未改动；完整性通过与优化指标改善是两个不同结论。
